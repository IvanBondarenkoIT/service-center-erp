# Аудит интерфейса и целевая схема (24.11.2026)

Аудит: копия `main` (коммит `6d1d11b`), SQLite с 9 тестовыми заказами, Chrome-эмуляция 390×844 (is_mobile, touch)
и 1366×900, роли admin, mechanic_batumi, accountant. Реальный телефон, камера, язык `ka` и печать не проверялись.

## Вывод

Интерфейс уже частично адаптивный (нижнее меню, карточки заказов, липкая «Сохранить»), переписывать с нуля не нужно.
Проблемы точечные, но бьют по ежедневной работе механика с телефона.

## Общие проблемы

- Поля ввода с font-size < 16 px → iOS зумит при фокусе. Форма заказа: 16 полей, кофеварки: 31, клиенты: 21.
- Material Symbols, IBM Plex, Noto Georgian грузятся с fonts.googleapis.com (`display=block`), HTMX — с unpkg.com.
  Без сети/на медленной сети вместо иконок видны слова `assignment`, `qr_code_scanner`, `payments`, `search`, `delete`,
  `photo_camera`, нижнее меню разъезжается.
- Тап-зоны < 40 px: RU/EN/GE, «Выход», чипы оплаты и типа строки, ссылки в таблицах, чекбокс «Без SN».
- Верхняя плашка на телефоне: языки и «Выход» занимают место на каждом экране; имя/роль скрыты.
- Нет `env(safe-area-inset-bottom)`, нет `theme-color` и manifest, `inputmode` не используется нигде.
- `<input>` без `type` не стилизуются (CSS ловит только `input[type=text|password|date|number|tel]`) — в
  `/dict/machines` и `/admin/users` поля выглядят как крошечные системные рамки (и на десктопе тоже).
- Брейкпоинты вперемешку: `max-width: 800px`, `max-width: 899px`, `min-width: 700/900/1200px`.

## Целевая схема на телефоне (< 900 px)

- **Каркас:** плашка 52 px — «назад» на вложенных экранах, заголовок экрана, инициалы → профиль. Языки и выход — в «Ещё».
  Внизу меню с safe-area; на формах над ним липкая панель действий.
- **Нижнее меню:** механик — Заказы · Приёмка (акцент) · Касса · Ещё; админ — Заказы · Приёмка · Касса · Отчёты · Ещё;
  бухгалтер — Касса · Отчёты · История · Ещё.
- **Ещё:** группы «Работа», «Справочники», «Администрирование» + профиль (имя, роль, СЦ, язык, выход), только разрешённое роли.
- **Список заказов:** поиск на всю ширину без кнопки, статусы одной строкой со скроллом, карточка в 3 строки, цель 4–5 на экран.
- **Приёмка:** Аппарат (большая «Сканировать SN», SN, модель, история свёрнута до счётчика) → Клиент → Причина → липкая «Принять».
- **Заказ:** сводка-шапка; секции-аккордеоны `<details>` (строки и описание открыты); строка-карточка; липкая панель
  «К оплате · Сохранить · Оплатить»; история — таймлайн человеческим языком. От 1200 px — две колонки.
- **Касса:** фильтр свёрнут в строку «01.11 – 24.11 · Батуми ▾», первой — «Касса на конец», таблицы → карточки (`.table-cards`).
- **Админка/справочники:** поиск → «Добавить» (раскрывается) → карточки; таблицы → `.table-cards`.

# Этап 3. Приёмка

Ветка: `feature/mobile-3-intake`. Файлы: `templates/orders/intake.html`, `templates/orders/_history*.html`,
`static/app.css`; `static/intake-scan.js` — только представление, логику распознавания не трогать.

Серийный номер — главный ключ истории аппарата, поэтому на телефоне приёмка начинается с аппарата.

## Задача

1. Порядок блоков: **Аппарат → Клиент → Причина/комментарий.** Переставляй разметку, не меняя name/id/hx-*.
   Проверь, что `hx-trigger="... scan-done"` и цели `#history-box`, `#client-history-box`, `#erp-model-suggest` работают
   после перестановки. На ≥ 900 px — две колонки: слева аппарат, справа клиент.
2. Блок «Аппарат»: первой — большая кнопка «Сканировать SN» на всю ширину (`#scan-camera-btn`), под ней поле SN
   моноширинным шрифтом, подсказка про запчасти без аппарата — мелким серым, далее модель с подсказками ERP.
   Статусы сканера (`#scan-status`, `#scan-hint`, `#scan-failed`) заметные, с иконкой.
3. История SN и история клиента (HTMX-парциалы): пусто — одна серая строка вместо крупного блока; есть записи —
   заголовок «История · N» и компактные строки (дата, причина, сумма, ссылка на заказ). Правь только шаблоны, не запросы.
4. Телефон клиента: `type=tel`, `autocomplete="tel"`, `inputmode="tel"`; имя — `autocapitalize="words"`.
5. «Принять» — в липкой панели над нижним меню (safe-area), без дубля в конце формы. После submit кнопка `disabled`
   со спиннером (если в `app.js` этого ещё нет) — защита от двойной отправки.

## Проверки

`pytest -q` (особенно `tests/test_intake.py`); `python scripts/ui_snapshots.py --name stage3 --compare stage2`.
